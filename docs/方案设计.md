## 1. 总体架构

```
┌─────────────────────────────────────────────┐
│  前端（WebView2 渲染）                       │
│  Vue 3 + TS + Pinia                          │
│  ┌─────────┐ ┌─────────┐ ┌───────┐ ┌──────┐ │
│  │ timer   │ │ tasks   │ │ stats │ │settings│ │
│  └────┬────┘ └────┬────┘ └───┬───┘ └──┬───┘ │
│       └───────────┴────┬──────┴───────┘     │
│              invoke() │ Tauri IPC           │
├────────────────────────┬────────────────────┤
│  Rust 后端（命令）       │ 系统集成            │
│  设置/任务/会话 读写      │ 托盘/通知/窗口事件   │
└────────────┬───────────┴────────────────────┘
             │ 原子写（tmp + rename）
     %APPDATA%\com.pomodoroflow.app\
       settings.json / tasks.json / sessions.json
```

**设计原则**

- **单一数据源**：今日统计、图表、任务投入全部从 `sessions.json`（会话记录）实时计算，不存在冗余聚合文件
- **薄后端**：Rust 只做存储与系统集成，业务逻辑（计时、统计）全在前端，便于测试与迭代
- **离线优先**：无任何网络请求，数据全本地

## 2. 技术选型结论

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Tauri 2 | 安装包 1.34MB / 内存 25MB，托盘·通知·热键插件齐全 |
| 前端 | Vue 3 + TS + Pinia | 组合式 API 适合多 store 协作；类型安全 |
| 链接器 | llvm-mingw（GNU 工具链） | 本机无 MSVC；rustup 自带精简 mingw 在大二进制上有启动缺陷（见 §8） |
| 图表 | 手写 SVG | 需求仅为柱状图/占比条，避免引入图表库 |
| 提示音 | WebAudio 合成 | 免音频素材文件 |
| 打包 | NSIS | Tauri 官方支持，按用户安装无需管理员 |

## 3. 前端设计

### 3.1 状态管理（Pinia store）

| Store | 职责 |
| --- | --- |
| `timer` | 计时状态机：阶段、剩余时间、开始/暂停/跳过/重置、轮次；触发会话记录、提示音、系统通知、托盘同步 |
| `settings` | 设置读写与清洗（范围夹取）、持久化（300ms 防抖） |
| `tasks` | 任务 CRUD、当前任务关联（localStorage 快存） |
| `stats` | 会话记录装载与追加；今日概览/每日序列/任务占比/累计与连续天数均为 computed 派生 |

### 3.2 计时核心算法（关键正确性设计）

```
剩余时间 = endAt - performance.now()   // 单调时钟，休眠/改系统时间不影响
endAt 仅在「开始/继续」时设置一次；暂停时把差值存回 remainingMs
```

- UI 每 200ms tick 刷新，但**不累计 tick**，无漂移
- 阶段流转状态机：专注完成 → `completedInCycle+1` → 达到间隔进长休息否则短休息；长休息结束 → 轮次清零回专注
- 跳过 ≠ 完成：跳过的专注只记时长、不计番茄数（需求 Q-03）；<30s 的跳过片段忽略

### 3.3 界面结构

底部三标签（计时/任务/统计，快捷键 1/2/3）+ 全局设置弹窗。计时页：阶段切换 → 环形倒计时 → 轮次点 → 当前任务选择器 → 控制栏 → 今日概览。

## 4. 后端设计（Rust 命令）

| 命令 | 说明 |
| --- | --- |
| `get_settings` / `save_settings` | 设置读写（serde camelCase 对齐前端） |
| `get_tasks` / `upsert_task` / `delete_task` | 任务 CRUD（BTreeMap 存储，按创建时间排序返回） |
| `get_sessions` / `append_session` | 会话记录（内存 Mutex + 全量落盘） |
| `set_tray_state` | 托盘提示文字与「开始/暂停」菜单项文字实时更新 |
| `get_stats` / `record_focus` | 旧版日聚合（兼容保留，新代码不使用） |

**原子写**：所有 JSON 写入先写 `*.json.tmp` 再 `rename` 替换，异常退出不损坏数据。

## 5. 数据模型

**数据目录解析**（便携优先，代码见 Rust `data_dir()`）：

1. exe 旁 `data-location.txt`（首行为路径）——显式指定
2. 安装目录同级 `data` 文件夹——便携模式（数据跟着应用走，重装系统应用不丢数据）
3. `%APPDATA%\com.pomodoroflow.app`——默认兜底

```jsonc
// tasks.json —— Map<id, Task>
{ "id": "…", "name": "完成某功能", "estimate": 2, "createdAt": 1794312204020, "doneAt": null }

// sessions.json —— 追加式数组，长期统计唯一数据源
{ "id": "…", "taskId": "…|null", "taskName": "快照名",   // 任务删除后历史仍可读
  "start": 1794312541713, "durationMs": 32002, "completed": false }

// settings.json
{ "focusMin": 25, "shortBreakMin": 5, "longBreakMin": 15, "longBreakInterval": 4,
  "autoStartBreaks": false, "autoStartFocus": false, "soundEnabled": true,
  "notifyEnabled": true, "volume": 70, "theme": "system",
  "locale": "zh-CN", "hotkeyEnabled": true }   // M3：界面语言 / 全局热键开关
```

> 坑位记录：`performance.now()` 为亚毫秒**浮点**，直接传给 Rust `u64` 会反序列化失败——所有跨 IPC 时间戳必须 `Math.round`。

## 6. 系统集成

- **托盘**：Rust 侧 `TrayIconBuilder` + 菜单（显示/开始|暂停/跳过/退出）；控制动作经 `emit("tray-action")` 到前端由 timer store 执行（单一计时真相源）；前端每秒 `set_tray_state` 同步倒计时
- **关闭到托盘**：`WindowEvent::CloseRequested` → `hide() + prevent_close()`，退出仅走托盘菜单
- **通知**：`tauri-plugin-notification`，前端在阶段结束时发送（内容区分"专注结束/休息结束"），设置可关
- **单实例**（M3）：`tauri-plugin-single-instance`（需为第一个插件），二次启动回调中唤起主窗口后自动退出
- **全局热键**（M3）：`tauri-plugin-global-shortcut`，`Ctrl+Alt+Space` 按下 → emit("global-hotkey") → 前端 timer.toggle()；按设置开关幂等注册/注销（is_registered 判重）
- **开机自启**（M3）：`tauri-plugin-autostart`（Windows 注册表 Run 键），命令 get/set_autostart，状态以系统为准回显
- **导出/导入**（M3）：内容在 TS 侧组装（本地时区时间可靠、CSV 带 BOM），Rust 仅 `rfd` 原生对话框 + 落盘（save_export / pick_import_file）；导入按会话 id 去重合并（merge_sessions），任务按 id 跳过已有
- **i18n**（M3）：手写双语字典（src/lib/i18n.ts，响应式 locale + t()），渲染期取词实现即时切换；托盘菜单全部文案由前端 set_tray_state 五参数同步
- **异常恢复**（M3）：read_json 解析失败时将损坏文件改名 \.corrupt-{ts} 留存并回退默认值，应用永不因数据损坏无法启动

## 8. 本机构建环境专项（无 MSVC 方案）

依赖全部位于 `D:\myself\envrionment\`（纯 ASCII 路径，规避中文用户名问题）：

| 组件 | 位置 | 说明 |
| --- | --- | --- |
| Rust GNU 工具链 | `rustup\`、`cargo\` | `RUSTUP_HOME`/`CARGO_HOME` 已写入用户环境变量 |
| llvm-mingw | `llvm-mingw\llvm-mingw-20261104-ucrt-x86_64\` | 链接器（`src-tauri\.cargo\config.toml` 指定），并已补 libgcc 兼容库 |
| rustc 重试器 | `retry-rustc.exe`（源码见 `scripts\retry-rustc.c`） | 兜底自动重试启动即崩的 rustc；stdio 白名单句柄隔离传递 |

**踩坑实录（按发现顺序）**：

1. **中文用户名路径** → GNU ld 读 @响应文件按 ANSI 解析中文路径失败 → 工具链整体迁至 D 盘 ASCII 路径
2. **GNU 工具链缺 dlltool** → 老 windows-sys 构建脚本需要 → 引入 llvm-dlltool（补齐 libLLVM/libc++/libunwind）
3. **rustup 自带精简 mingw 运行时缺陷** → 构建脚本与 rustc 大二进制启动即崩（STATUS_ACCESS_VIOLATION）→ 换 llvm-mingw 完整运行时
4. **旧 proc-macro DLL 中毒**（坏链接器时代产物）→ rustc 加载 tauri_macros/serde_repr DLL 必崩 → 删除重编即愈
5. **cmd.exe 8191 字符命令行上限** → `windows` crate 巨型 `--check-cfg` 命令被截断 → 重试器改为 CreateProcess 直启（上限 32K）
6. **浮点时间戳** → 见 §5 坑位记录
