## 1. 项目概述

### 1.1 背景

番茄工作法（Pomodoro Technique）是广泛使用的专注力管理方法：以 25 分钟专注 + 5 分钟短休息为一个循环，每 4 个循环后进行 15 分钟长休息。现有工具或功能臃肿、或依赖联网账号、或缺乏统计能力。

### 1.2 产品定位

PomodoroFlow 是一款**轻量、离线优先、开箱即用**的 Windows 桌面番茄钟，帮助用户规划专注时段、关联任务、回顾专注数据，形成"专注 → 记录 → 反馈"的完整闭环。

### 1.3 设计原则

1. **本地优先**：所有数据存储在本地，无需注册、无需联网。
2. **零打扰**：专注期间不打断用户，通知只在阶段切换时出现。
3. **一目了然**：任何时刻瞥一眼就能知道剩余时间和当前任务。
4. **够用就好**：核心流程极简，高级功能（白噪音、严格模式等）可选项提供，不增加理解成本。

### 1.4 范围界定

| 本期范围（In Scope） | 不做（Out of Scope） |
| --- | --- |
| 计时、任务、通知、统计、设置 | 云同步、多端 |
| 本地数据导出/导入 | 账号系统、协作功能 |
| 系统托盘、全局热键、开机自启 | 移动端 / macOS / Linux |
| 中英文界面 | 浏览器插件、第三方日历集成 |

## 2. 目标用户与使用场景

### 2.1 目标用户

- **程序员 / 知识工作者**：需要长时间深度专注，希望量化每天的专注时长。
- **学生**：备考、写作业时需要外部节奏约束。
- **自由职业者**：以番茄数计量工作量，回顾时间投入。

### 2.2 典型场景（用户故事）

| 编号 | 用户故事 | 对应功能 |
| --- | --- | --- |
| US-01 | 作为用户，我想一键开始一个番茄钟，以便立刻进入专注状态 | 计时核心 |
| US-02 | 作为用户，我想给番茄钟绑定一个任务，以便知道"这个番茄是为了什么" | 任务管理 |
| US-03 | 作为用户，我想在专注结束时收到提醒，即使窗口最小化了也不错过 | 通知提醒 |
| US-04 | 作为用户，我想查看今天/本周专注了多久，以便回顾时间去向 | 统计报表 |
| US-05 | 作为用户，我想用键盘快捷键控制计时，不切换窗口也能暂停 | 全局热键 |
| US-06 | 作为用户，我想调整番茄/休息时长，以匹配自己的节奏 | 设置 |

## 3. 功能需求

优先级定义：**P0** = 首个可用版本必须具备；**P1** = 正式发布版应具备；**P2** = 加分项，可迭代。

### 3.1 计时核心（P0）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-101 | 支持三种阶段：专注（Focus）、短休息（Short Break）、长休息（Long Break），默认时长 25 / 5 / 15 分钟，可自定义（1–120 分钟） | P0 |
| FR-102 | 阶段流转规则：完成 N 个专注（默认 4 个）后自动进入长休息，其余进入短休息；N 可配置 | P0 |
| FR-103 | 计时控制：开始、暂停、继续、跳过当前阶段、重置当前阶段 | P0 |
| FR-104 | 自动流转可配置：专注结束后是否自动开始休息、休息结束后是否自动开始下一个专注（默认均关闭，需手动确认） | P1 |
| FR-105 | 主界面以**环形进度 + 数字倒计时（mm:ss）**展示剩余时间，当前阶段（专注/短休/长休）有明显视觉区分 | P0 |
| FR-106 | 计时基于单调时钟（monotonic clock），系统休眠/睡眠恢复后时间计算正确，不因系统时间被修改而错乱 | P0 |
| FR-107 | 阶段进行中，应用标题栏 / 任务栏图标实时显示剩余时间 | P1 |

**验收标准（FR-101~103）**：
- 从点击"开始"到阶段结束的误差 ≤ 1 秒。
- 暂停后剩余时间保持不变；继续后从暂停点继续。
- 跳过专注阶段也计入"完成的番茄数"的规则需在设置中明确（见 FR-301，默认跳过不计入）。

### 3.2 任务管理（P0）

| FR-202 | 开始专注前可选择"当前任务"，该次专注记录与任务关联 | P0 |
| FR-203 | 任务上展示实际投入的番茄数 / 专注时长，与预估值对比 | P1 |
| FR-204 | 已完成任务归档展示（当日完成），支持按完成日期查看历史任务 | P2 |
| FR-205 | 今日待办视图：默认只显示今天创建或未完成的任务 | P1 |

| FR-302 | 通知内容区分场景：专注结束（提示休息）、休息结束（提示回到专注） | P0 |

## 4. 非功能需求

## 5. 技术选型建议

三个候选方案对比（推荐 **方案 A**）：

| 维度 | 方案 A：Tauri 2 + Vue 3（推荐） | 方案 B：Electron + Vue 3 | 方案 C：WPF (.NET 8) |
| --- | --- | --- | --- |
| 安装包体积 | ~10–15MB | ~80–100MB | ~50–70MB（含运行时） |
| 内存占用 | 低（~40–80MB） | 高（~150–250MB） | 低–中 |
| UI 表现力 | Web 技术，现代感强 | Web 技术，现代感强 | 原生，自定义样式成本较高 |
| 系统集成（托盘/热键/自启/通知） | 官方插件齐全 | 生态最成熟 | 原生支持最好 |
| 开发效率 | 高（前端技术栈），Rust 后端有一定学习成本 | 最高 | 中（需 C#/XAML） |
| 作品集加分 | 高（体积与性能优势明显，技术新） | 中 | 中 |

**推荐理由**：PomodoroFlow 功能以 UI 和轻量系统集成为主，无重后端逻辑，Tauri 2 的插件（tray、global-shortcut、notification、autostart）恰好全覆盖需求，且产物小、内存低，与"轻量桌面工具"的定位一致。Rust 侧仅需极薄的一层（读写本地 JSON/SQLite），学习成本可控。

若希望完全避开 Rust、追求最快出活，选 Electron；若想突出 Windows 原生开发能力，选 WPF。

**技术要点（以方案 A 为例）**：

- 前端：Vue 3 + TypeScript + Vite，Pinia 状态管理，UI 组件可自绘（环形倒计时建议 SVG/Canvas 自绘）。
- 计时：前端 `setInterval` 驱动 UI 刷新，剩余时间由「截止时刻 - 单调时钟当前值」计算，避免累计漂移。
- 数据：设置存 JSON 文件；任务与专注记录存 SQLite（`rusqlite`/`tauri-plugin-sql`），便于统计查询。
- 图表：Chart.js 或 ECharts。
- 打包：`tauri build` 产出 NSIS 安装包（`.exe`）与 MSI。

## 6. UI / UX 设计要求

| 编号 | 要求 |
| --- | --- |
| UX-01 | 主窗口建议尺寸约 360×520（竖版卡片式），信息层级：倒计时环 > 当前任务 > 控制按钮 > 今日概览 |
| UX-02 | 三种阶段用颜色语言区分：专注=主题色（如番茄红/靛蓝）、短休息=绿、长休息=蓝；颜色随主题可配 |
| UX-03 | 支持浅色 / 深色 / 跟随系统 三种主题 |
| UX-04 | 阶段切换时给轻量动效（进度环过渡、按钮状态变化），不使用打断式全屏弹窗 |
| UX-05 | 空状态有引导文案（如"添加一个任务，开始第一个番茄"） |

## 8. 整体验收标准（发布门槛）

1. 全部 P0 需求通过测试，P1 完成率 ≥ 90%。
2. 在 Windows 10 与 Windows 11 上各完成一轮完整手动回归：安装 → 首次启动 → 完成一组「专注-短休-专注-长休」循环 → 查看统计 → 重启后数据完整。
3. 计时精度、睡眠唤醒恢复、DPI 缩放三项通过专项测试。
4. 无网络环境下功能全部正常（验证 NFR-04）。
